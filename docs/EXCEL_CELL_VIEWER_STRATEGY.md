# Argo 엑셀 셀 단위 뷰어 — 시트별 구현 전략 (샘플 `Excel_Masterclass_95Percent_Advanced_Suite.xlsx` 기준)

작성: 2026-11-10 · 대상: tvOS 16 / Argo (TrollStore) · 코드 작업은 아직 시작하지 않음 (이 문서는 방향과 순서만 정한다)

근거 자료
- 샘플 파일을 직접 풀어 시트별로 센 값 (아래 3절).
- 이전 대화 「엑셀 뷰어 코드 작성 지침」(2026-11-05)의 15개 절 사양과 95% 정의. 이 문서는 그 사양을 **이 샘플 7개 시트에 맞춰 줄인 적용판**이다.
- LibreOffice 로 다시 계산한 정답 값 1,208개 (`golden_values.json`, 오류 0건).

## 1. 결론 (먼저 읽을 것)

1. **이 샘플은 계산된 값(캐시)이 하나도 없다.** 수식 셀 1,208개가 모두 `<v></v>` 이고 통합 문서에 `fullCalcOnLoad="1"` 이 켜져 있다 (openpyxl 로 만든 파일). 따라서 뷰어가 **스스로 계산하지 못하면 수식 칸이 전부 빈칸**이다. 지금의 PDF 변환 경로는 `SUM` 과 덧셈만 계산하므로(`minipdf/src/xlsx.rs` `evaluate_simple_formula`) 이 파일에서는 사실상 쓸 수 없다. → **수식 엔진이 셀 뷰어보다 먼저 필요하다.**
2. 이전 대화에서 정한 구조를 그대로 쓴다: Rust `argosheet` 크레이트(모델·서식·수식·그리기 목록) + Swift 는 타일만 그린다 + 셀 커서는 하나. **셀마다 포커스 받는 UICollectionView, NSExpression, CoreXLSX, NumberFormatter 흉내는 쓰지 않는다.**
3. 이 샘플이 쓰는 기능만 보면 필요한 함수는 **64개**, 서식 코드는 **6종**, 조건부 서식은 **3종 + 아이콘 1종**, 차트는 **막대 2 + 선 1** 이다. 이전 사양의 "함수 약 120개"는 이 샘플에는 과하다. 1차는 64개로 95% 를 만들고 나머지는 뒤로 둔다.
4. 합격선은 이전 사양의 5지표를 이 샘플에 맞춘 것: **정답 1,208칸 중 1,196칸 이상(99%) 일치, 표시 문자열 99.5%, 틀 고정·필터·메모·유효성·차트가 시트별 체크리스트 통과**.
5. 빌드·릴리즈는 단계 끝 3번(P2·P5·P6)만. 나머지는 CI 단위 시험으로 넘긴다 (기존 방침과 같음).

## 2. 현재 상태와 문제

| 항목 | 현재 (PDF 경로) | 목표 (셀 뷰어) |
| --- | --- | --- |
| 표시 | 시트를 쪽으로 잘라 PDF → CoreGraphics. 넓은 시트는 쪽이 나뉜다 | 시트 하나를 스크롤·확대. 셀 단위 이동 |
| 수식 | SUM·덧셈만 계산 | 64개 함수 자체 계산, 참조·다른 시트·이름 |
| 틀 고정·필터·메모·유효성 | 없음 | 있음 (이 샘플의 01 시트가 전부 사용) |
| 입력 | 보기만 | 셀 커서 + 수식 막대. 목록(유효성) 선택, 숫자 다시 넣기는 후반 |
| 비교 도구 | `MediaFolderProbe` 는 xlsx 를 제외 (쪽 나누기가 PC와 달라서) | 시트별 렌더 vs 정답 값/그림 비교 가능 |

문제가 되는 점
- 캐시 없음 → 모든 시트에서 "값이 안 나옴" (1,208칸).
- 시트 `06` 의 `STDEV.S`·`STDEV.P`·`VAR.S` 는 파일에 `_xlfn.` 접두어 없이 적혀 있다. 실제 엑셀·LibreOffice 는 이 파일을 열면 해당 39칸을 `#NAME?` 으로 보여 준다(LibreOffice 로 확인). **뷰어는 접두어가 없어도 계산해 주는 쪽(관대한 쪽)으로 정한다** — 작성자의 의도가 값이고, `#NAME?` 은 만든 도구의 결함이기 때문. 정답 값은 접두어를 붙인 사본으로 다시 계산해 만들었다.

## 5. 시트별 구현 전략

각 항목: 무엇을 보여야 하나 → 어떻게 만드나 → 합격 확인.

### 5.0 모든 시트에 공통으로 먼저 필요한 것 (P0·P1)
- ZIP 읽기, `workbook.xml`(시트 목록·정의된 이름·`calcPr`), `styles.xml`(서식 코드·글꼴·채우기·테두리·정렬), `theme1.xml`, 시트 XML 스트리밍 파싱(quick-xml), 인라인 문자열, 병합, 열 너비·행 높이.
- 열 너비(문자 단위) → pt 환산은 `excel_column_width_to_points_with_mdw` 를 그대로 사용.
- 수식 문자열 파서(토큰 → 구문 트리) + 값 모델(숫자·문자·논리·오류·빈 칸·날짜는 숫자) + 셀 의존 그래프 + 전체 재계산. `fullCalcOnLoad=1` 이면 열 때 전부 계산한다.
- 합격: `argosheet-cli dump` 가 7개 시트의 셀 원래 값과 수식을 출력, 수식 칸 1,208개를 모두 구문 분석(분석 실패 0).

### 5.1 시트 00 — 종합목차_및_대시보드
- 보일 것: 제목(병합 A1:J1, A2:J2), 목차 표, 시트 이동 링크 6개, 요약 수치, I10:I15 데이터 막대, 막대 차트.
- 구현
  - `HYPERLINK("#'시트명'!A1","▶ 01번 시트 이동")` → 표시 글은 두 번째 인수, 눌렀을 때(선택 버튼) 시트 전환 + A1 커서. 외부 주소가 오면 QR 모달(이전 사양 18번 버그 수정판 사용).
  - SUMIF·IFERROR·ISNUMBER·MAX·IF·AVERAGE 는 5.7 의 공통 함수군.
  - 데이터 막대: `cfvo num 0 ~ 1`, 색 `0F766E`, 값 표시. 막대 길이 = (값−0)/(1−0), 범위 밖은 자름. 막대는 셀 글 뒤에 그린다.
  - 차트: `oneCellAnchor`(열 4, 행 17)에 세로 막대(묶음). 참조 `A20:A24`(항목)·`B20:B24`(계열1)·`C19` 제목. 차트 렌더는 기존 슬라이드 쪽 `argoconv/src/slides/chart.rs` 의 막대 그리기를 **재사용 후보**로 본다(5.8).
- 합격: 링크 6개가 시트를 정확히 옮기고, 막대 6개 길이가 정답 값 비율과 같고, 차트 위치가 셀 경계와 맞는다.

### 5.2 시트 01 — 원본데이터_유효성_테이블 (가장 무거운 시트)
- 보일 것: 60행 × 19열 데이터, **A~D열·1~4행 틀 고정**, 필터 단추(A4:S64), 열 N 데이터 막대, 열 Q 3색 색조, 메모 표시(A4·D4·M4 등 4건), 계산 열(IF 240·ROUND 180·NETWORKDAYS 120).
- 구현
  - **틀 고정**: `pane xSplit=4 ySplit=4 topLeftCell=E5 state=frozen`. 모서리·위·왼쪽·본문 4구역. 본문을 스크롤하면 위·왼쪽이 같은 오프셋을 따라간다(이전 사양 3.4절).
  - **자동 필터**: P2 에서는 머리글에 단추 표시만. 눌러서 거르기는 P6(선택). `_xlnm._FilterDatabase` 로 범위를 얻는다.
  - **데이터 유효성**: 목록 2(D열 권역 `NA,EU,APAC,LATAM,MEA`는 인라인 목록, R열 신용등급 `"AAA,AA,A,BBB,BB"`), 소수 1(M열 0%~35%). `showErrorMessage=0` 이므로 **입력을 막지 않고** 입력 안내(`prompt`)만 띄운다. 셀에 커서가 오면 안내를 보인다. 목록은 선택 버튼 → 목록 선택 창.
  - **메모**: `comment1.xml` + VML. 메모가 있는 셀 오른쪽 위에 작은 빨간 삼각형, 커서가 오면(또는 선택) 작성자(4명)와 내용을 보인다. VML 의 위치 상자는 무시해도 된다.
  - **데이터 막대**: `cfvo min~max`, 색 `3B82F6`. **색조**: `min`·`percentile 50`·`max` = `FCA5A5`·`FFFFFF`·`86EFAC` (보간은 RGB 선형).
  - **서식**: `yyyy-mm-dd`, `$#,##0.00;($#,##0.00);"-"`, `0.0%`. 음수는 괄호, 0 은 `-`.
  - **함수**: `NETWORKDAYS(시작, 끝)` 은 주말(토·일)만 제외(휴일 인수 없음). `ROUND` 는 0에서 먼 쪽(엑셀 규칙). `SUBTOTAL(109·…)` 은 숨겨진 행·필터된 행 제외 규칙까지 구현.
  - **정의된 이름**: `RNG_REV` 등 9개 → 이름 표에 넣고 수식 파서가 해석.
- 합격: 수식 248칸 정답 일치, 틀 고정이 스크롤 중 유지, 메모 4건 표시, 유효성 3건 안내 문구 표시, 색조·막대 색이 LibreOffice 렌더와 육안 동일.

### 5.3 시트 02 — 고급수식_논리_조회_배열
- 보일 것: 조회 결과 표(INDEX/MATCH 51, VLOOKUP 31), 합계·집계(SUMPRODUCT 23, SUMIFS·COUNTIFS·AVERAGEIF 5씩), RANK 5, LARGE 10, 입력 칸 B6·B7 (다른 시트 범위를 가리키는 목록).
- 구현
  - **참조 해석**: `'01_원본데이터_유효성_테이블'!$A$5:$A$64` 같은 다른 시트 범위, 절대·상대 참조, 이름 범위.
  - **조회군**: `MATCH(값, 범위, 0|1|-1)`, `INDEX(범위, 행, 열)`, `VLOOKUP(값, 표, 열, 정확여부)`, `CHOOSE`, `OFFSET`(변하는 참조라 재계산 그래프에서 **의존 범위를 실행 중에 정한다** — 이 시트 한 곳뿐이므로 OFFSET 이 있는 칸은 "항상 다시 계산" 표시로 단순 처리), `ADDRESS`.
  - **집계군**: `SUMPRODUCT`(배열 곱 합, 불리언 곱을 숫자로), `SUMIFS/COUNTIFS/AVERAGEIF`(조건 문자열 `">=100"`, 와일드카드 `*`·`?`), `LARGE`, `RANK`.
  - **유효성 목록**: 수식 `='01_…'!$A$5:$A$64`(앞에 `=` 가 붙어 있다 — 엑셀 규격과 달라서 **앞의 `=` 를 벗기고** 해석한다), `'01_…'!$A$4:$S$4`. B6·B7 을 바꾸면 이 시트의 의존 칸이 다시 계산된다 → **편집(P6)의 첫 시험대**. 1차(보기 전용)에서는 저장된 선택값으로 계산한다.
  - 글자 칸(예: `OFFSET(A4, 행변위, 열변위, 1, 1)` 같은 설명문)은 수식이 아니라 **문자**다. 수식 판정은 `<f>` 요소로만 한다.
- 합격: 186칸 정답 일치, 오류 값(`#N/A` 등)이 나올 칸은 정답과 같은 오류 문자열로 표시(IFERROR 로 가려지는 칸은 가려진 값).

### 5.4 시트 03 — 텍스트_날짜_데이터가공
- 보일 것: 공백·기호가 섞인 로그 문자열 25행을 가공(TRIM/SUBSTITUTE/MID/FIND/RIGHT/PROPER), 날짜 계산(DATEDIF·NETWORKDAYS·EOMONTH·EDATE·WEEKDAY), `REPT("■")` 막대와 `TEXT(J6,"00")`.
- 구현
  - 문자열 함수는 **엑셀 글자 수 규칙**대로: 한글 1글자 = 1, `FIND` 는 대소문자 구분·와일드카드 없음·1부터 시작·못 찾으면 `#VALUE!`. `MID(문자, 시작, 길이)` 경계, `TRIM` 은 앞뒤 공백 제거 + 안쪽 연속 공백을 1칸으로, `PROPER` 는 각 단어 첫 글자만 대문자(`kim minsu` → `Kim Minsu`).
  - `xml:space="preserve"` 인 앞뒤 공백 보존(원문 A열은 공백 포함이어야 TRIM 결과가 맞는다).
  - 날짜: 1900 날짜 체계(윤년 버그 1900-02-29 포함), 시리얼 ↔ 연월일. `EOMONTH`, `EDATE`(월 끝일 보정), `DATEDIF(…,"d")`(그 외 "m","y" 도 같이), `WEEKDAY(날짜, 2)`.
  - `TEXT(값, "00")` 는 `numfmt` 엔진을 호출한다(함수가 서식 엔진을 쓰는 첫 사례 → 엔진은 문자열 입력도 받게 설계).
  - `■`·`□` 반복 막대는 일반 글자로 그린다(글꼴 대체: Pretendard 에 없는 글리프는 기기 글꼴로 대체, 없으면 두부 표시 — 알려진 한계).
- 합격: 325칸 정답 일치. 이 시트는 **함수 규칙 시험용으로 가장 좋다**(수식 칸이 많고 서식이 단순).

### 5.5 시트 04 — 피벗크로스탭_다차원집계
- 보일 것: 권역 × 제품(또는 채널) 교차표 B6:F10 3색 색조(`F8FAFC`→`BAE6FD`→`0284C7`), 합계 행·열, 비율 표, 막대 차트.
- 구현
  - `SUMIFS` 50 + `SUM` 31 이 중심. **성능 점검 지점**: 원본 60행이라 가볍지만, 같은 패턴이 수만 행이면 SUMIFS 가 O(칸×행)이 된다 → 조건 열 색인(첫 호출 때 열을 한 번 읽어 해시) 설계를 처음부터 넣어 둔다.
  - 피벗 재집계는 제외(이전 사양 4.2). 이 시트는 진짜 피벗 표가 아니라 **SUMIFS 로 만든 교차표**이므로 일반 수식으로 처리된다.
  - 색조는 5.2 와 같은 코드를 쓴다(색 정지점만 다름).
  - 차트: 세로 막대 묶음, 항목 `A6:A10`, 계열 `B6:B10`·`C…`, 위치 열 0·행 21.
- 합격: 126칸 정답 일치, 색조 25칸 색 육안 동일, 차트 막대 높이 정답 비율 일치.

### 5.6 시트 05 — 재무모델링_DCF_감가상각
- 보일 것: 현금흐름 표와 NPV·IRR·MIRR, 감가상각 4방식(SLN·DB·DDB·SYD), 대출 상환(PMT·IPMT·PPMT), 색조.
- 구현 (엑셀과 **정확히 같은 정의**가 필요한 함수들)
  - `NPV(rate, 값…)` 은 첫 값을 1기 말로 할인(0기 아님). 18칸.
  - `IRR` 은 뉴턴법 + 이분법 보강(초기값 0.1, 최대 반복 20~50, 허용오차 1e-7 — 엑셀은 실패하면 `#NUM!`). `MIRR(값, 대출이자율, 재투자율)`.
  - `SLN(원가, 잔존, 수명)`, `SYD(원가, 잔존, 수명, 기간)`, `DDB(원가, 잔존, 수명, 기간, 계수=2)`(마지막 기간에 잔존가 아래로 안 내려감), `DB(원가, 잔존, 수명, 기간, 첫해월수=12)` — **DB 의 율은 소수 셋째 자리로 반올림**하는 엑셀 규칙을 반드시 지킨다(정답 값과 어긋나기 쉬운 곳).
  - `PMT/IPMT/PPMT(rate, nper, pv, fv=0, type=0)` 부호 규칙(대출 받은 돈 +, 갚는 돈 −).
  - 숫자 표시: `$#,##0;($#,##0);"-"` 와 `0.0000`. 괄호 음수·0 은 `-`.
- 합격: 145칸 정답 일치(상대오차 1e-9 이내). **이 시트의 정답이 가장 쉽게 어긋난다**(DB 율 반올림, NPV 기준 시점) — 먼저 단위 시험 벡터를 만든다.

### 5.7 시트 06 — 통계회귀_예측_조건부서식
- 보일 것: 월별 R&D 투자·수주 데이터 18행, 회귀 통계(SLOPE·INTERCEPT·RSQ·CORREL), 예측(FORECAST 19), 잔차·Z 점수·MAPE, 이상치 판정 문자열, **3색 색조(G)**, **데이터 막대(J)**, **아이콘 집합(F열 화살표)**, 선 차트.
- 구현
  - 통계 함수 정의: `STDEV.S`(n−1)·`STDEV.P`·`VAR.S`, `MEDIAN`, `QUARTILE`/`PERCENTILE`(**포함 방식 선형 보간**), `FORECAST(x, 알려진y, 알려진x)`, `SLOPE`·`INTERCEPT`·`RSQ`·`CORREL`.
  - 접두어 없는 `STDEV.S` 등을 받아들인다(2절의 결정). 이름 표에 `STDEV.S` 와 `_xlfn.STDEV.S` 둘 다 등록.
  - **색조** G열: `min → 93C5FD`, `num 0 → FFFFFF`, `max → FCA5A5` (0 이 가운데 지점, 양쪽 따로 보간).
  - **데이터 막대** J열: 0~1 고정, 색 `10B981`.
  - **아이콘 집합** F열 `3Arrows`: 임계값이 `-15`, `15` 두 개만 적혀 있다(`cfvo num`). 규칙: 값 ≥ 15 → 위 화살표(초록), −15 ≤ 값 < 15 → 옆(노랑), 그보다 작으면 아래(빨강). `showValue=1` 이므로 숫자도 같이 그린다. 아이콘은 벡터로 그린다(이미지 아님). 20종 중 이 샘플은 1종이지만 **3종 묶음 구조(임계 2개·방향 규칙)만** 먼저 만들고 나머지 집합은 같은 틀에 표만 늘린다.
  - 차트: 선(표준), 항목 `A6:A23`(월), 계열 `C…`(실제)·`D…`(추정), 위치 열 0·행 24. 날짜 항목은 `yyyy-mm` 서식으로 축 레이블.
- 합격: 141칸 정답 일치, 3종 조건부 서식 육안 동일, 차트 두 선의 점 18개 위치가 정답 값과 같다.

### 5.8 차트(3개) 처리 방침
- 이전 사양은 그림·도형·차트를 P5 에 둔다. 샘플 차트는 단순(막대 2, 선 1)하므로 **슬라이드 쪽 차트 렌더러(`argoconv/src/slides/chart.rs`)를 재사용**하는 안을 1순위로 한다: 차트 XML 파싱과 막대·선 그리기가 이미 있고, 최근 눈금 간격 규칙(칸 수 10 이하의 1·2·5 간격)과 쌓은 그래프 범례 순서도 고쳐 두었다.
- 셀 값에서 오는 계열(`<c:f>` 참조)은 **수식 엔진이 계산한 값**으로 채워야 한다(차트 안 캐시도 비어 있을 수 있음 → 시트 값을 직접 읽는 방식으로 연결).
- 위치는 `oneCellAnchor`(시작 셀 + 크기 EMU)를 엑셀 pt 좌표로 변환해 타일 위 별도 층에 올린다.

## 10. 위험과 열린 질문

1. **STDEV.S 접두어**(2절): 관대하게 계산하기로 했다. 엑셀과 다르게 보이는 점이므로 이견이 있으면 알려 달라(엑셀 그대로 `#NAME?` 로 보이게 할 수도 있다).
2. **글꼴 글리프**: `▶ ■ □ ★ Ŷ β` 는 Pretendard 에 일부 없을 수 있다. 기기 글꼴 대체로 해결되는지 P3 에서 확인한다(한자 '社' 가 두부로 나오는 기존 문제와 같은 종류).
3. **수식 정확도**: 05 시트(DB·NPV·IRR)와 03 시트의 `FIND`·`TEXT` 가 가장 틀리기 쉽다. 단위 시험 벡터를 먼저 만든다.
4. **편집·저장(P6)** 은 범위가 크다. 합격선을 "보기"에 두고 편집은 02 시트의 목록 선택 정도로 시작할 수 있다. 어디까지 할지 결정이 필요하다.
5. **기존 PDF 경로**는 유지한다(.xls·큰 파일·실패 시 대체). 새 뷰어는 켜고 끌 수 있는 스위치를 둔다.
6. 이 문서는 방향 문서다. 코드는 지시 후 시작하며, 한 번에 한 단계씩 Rob 의 확인을 받고 진행한다.
