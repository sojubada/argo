# 두 칸 파일 탐색기

윈도우 탐색기·토탈 커맨더처럼 **왼쪽에서 복사해 오른쪽에 붙여넣는** 화면.

## 왜 필요한가

지금은 파일을 고른 뒤 복사 아이콘을 누르면 **목적지를 고르는 시트가 뜹니다.**
리모컨으로 폴더를 하나씩 파고 들어가 목적지를 찾아야 해서 번거롭습니다.
두 칸이면 **오른쪽 칸이 이미 목적지**라 고를 일이 없습니다.

가장 값어치 있는 조합은 **왼쪽 = 애플TV, 오른쪽 = NAS(WebDAV)** 입니다.
칸마다 로컬인지 WebDAV인지 따로 정할 수 있어야 합니다.

## 화면

```
┌──────────────────────────────────────────────────────────┐
│  [선택] [복사] [붙여넣기] [이동] [압축] [휴지통] [설정]      │  ← 툴바
├───────────────────────────┬──────────────────────────────┤
│ ◆ /var/mobile/Media       │   webdav:/NAS/문서            │
│   ├ 보고서.docx            │     ├ 2025예산.xlsx           │
│   ├ 사진                   │     ├ 회의록.hwp              │
│   └ 자료.pdf               │     └ 백업                    │
└───────────────────────────┴──────────────────────────────┘
          활성 칸                      비활성 칸
```

- **활성 칸**은 테두리와 경로 앞의 `◆` 로 구분합니다. 비활성 칸은 어둡게
- 복사·이동·압축은 **활성 칸의 선택 항목**에 대해 동작하고, 붙여넣기는 **반대 칸**으로 갑니다
- 55인치를 3미터에서 봅니다. 칸이 반으로 줄어드니 **파일명이 잘립니다.**
  활성 칸을 60%, 비활성 칸을 40%로 넓혔다 줄이는 방식을 권합니다

## 리모컨 이동 규칙

가로축이 이렇게 이어집니다.

```
툴바  ←  왼쪽 칸  ⇄  오른쪽 칸  →  툴바
```

| 지금 위치 | 누른 방향 | 결과 |
|---|---|---|
| 왼쪽 칸 | ← | 툴바로 |
| 왼쪽 칸 | → | 오른쪽 칸으로 |
| 오른쪽 칸 | ← | 왼쪽 칸으로 |
| 오른쪽 칸 | → | 툴바로 |
| 양쪽 칸 | ↑ ↓ | 칸 안에서 위아래 |
| 양쪽 칸 | 메뉴 | 상위 폴더로 |

대칭입니다. 가운데는 오가고, 바깥 끝은 툴바로 빠집니다.

## tvOS에서 어려운 지점

**칸 사이 이동은 공짜입니다.** 칸 두 개를 나란히 두면 포커스 엔진이 알아서
좌우로 건너갑니다. 손댈 것이 없습니다.

**손댈 곳은 바깥 끝에서 툴바로 빠지는 것 하나뿐입니다.** 툴바는 칸 위에
있으니 ↑ 로도 갈 수 있지만, 목록 아래쪽에 있을 때 맨 위까지 올라가야 하는
것은 번거롭습니다. 그래서 ← / → 로 바로 빠지게 합니다.

`UIFocusGuide` 를 양쪽 바깥에 하나씩 두고 `preferredFocusEnvironments` 를
툴바로 지정하면 됩니다. **포커스 가이드가 정확히 이 일을 하라고 있는
물건이라** 기본 동작과 싸우지 않습니다.

## 선행 조건

- 칸마다 **독립적인 경로·선택 상태**가 필요합니다. 지금 `ContentView` 는
  `directory`, `multiSelectFiles` 를 하나씩만 들고 있습니다
- 파일 목록을 그리는 부분을 **재사용 가능한 뷰로 떼어내야** 합니다.
  지금은 `ContentView` 본문에 박혀 있습니다
- WebDAV 목록도 같은 뷰를 쓸 수 있어야 합니다

적지 않은 수술입니다. **문서 읽기가 정리된 뒤에 손대는 것이 맞습니다.**
