# 변환기 코드 조사 — 무엇을 고치고, 무엇을 다시 써야 하는가

MiniPdf(벤더링했으므로 우리 코드다)와 hwpers 를 읽고 나온 것들이다.
증상에서 출발해 실제 줄까지 짚었고, 추측은 추측이라고 적었다.

## 1. 워드 표 테두리 — 스타일 ID 가 박혀 있다

`docx.rs:1116`

```rust
let style_has_grid = style_id == Some("af2");
```

`af2` 는 개발자가 시험한 어느 문서의 스타일 ID 다. 보통 Word 문서의
`Table Grid` 는 `TableGrid` 라 여기에 걸리지 않는다. 그래서 스타일로 테두리를
주는 표는 선이 하나도 안 나온다.

그리고 표 수준 테두리는 **읽기만 하고 쓰지 않는다**:

```rust
let use_style_borders = style_has_grid
    && properties.and_then(|node| child(node, "tblBorders")).is_none();
```

`tblBorders` 는 스타일 대체를 *끄는* 용도로만 쓰이고, 그 안의 값은 버려진다.
`read_cell_border` 는 `tcBorders` 만 본다.

시험으로 확인했다 — 스타일(`Table Grid`)로 준 표와 인라인 `w:tblBorders` 로
준 표, **둘 다** 선이 없었다. 위 두 줄이 정확히 그 두 경우다.

**고칠 방법**: 셀 테두리 해석 순서를 `tcBorders` → 표의 `tblBorders` →
`tblStyle` 이 가리키는 styles.xml 의 `tblBorders` → 없음 으로 둔다.
`af2` 비교는 지운다. 그리는 코드(`draw_border`)는 이미 멀쩡하다.

**크기**: 작다. **값어치**: 크다 — 문서 하나가 아니라 부류 전체가 고쳐진다.

## 2. 엑셀 쪽 나누기 — 인쇄하듯 쪼갠다

넓은 시트를 열 묶음별로 잘라 여러 쪽에 흩뿌린다. 종이에는 맞지만 화면으로
따라 읽을 수가 없다. 사용자가 지적한 그대로다.

다행히 지렛대가 이미 있다. `xlsx.rs:3855 render_sheet` 는

- `page_setup.fit_to_width` 가 켜지면 열을 자르지 않고 줄여서 한 쪽에 넣고
- `render_xlsx` 는 `page_size_override: Option<PageSize>` 를 받으며
- `ConversionOptions { page_size }` 로 바깥까지 열려 있다

**고칠 방법**: TV 용 모드를 하나 둔다 — 쪽 **폭을 시트 전체 폭 + 여백**으로
잡고 높이는 그대로 둔다. 그러면 열은 한 번도 안 잘리고, 행만 아래로 넘어간다.
뷰어의 '가로 꽉참' 이 표 전체 폭을 보여주고 아래로 읽어 내려가면 된다.
글자를 줄이지 않아도 되는 것이 `fit_to_width` 보다 나은 점이다.

**크기**: 중간. `xlsx.rs` 가 6,642 줄로 가장 크지만 손댈 곳은 쪽 크기를
정하는 한 곳이다.

## 3. PPT — 제목은 고쳤고, 남은 둘

제목이 사라지던 것은 레이아웃이 마스터의 위치를 덮어쓰던 문제였고 고쳤다
(`pptx.rs`, 자리표시자 겹치기).

실기기 사진에서 남아 보이는 것:

- **도형이 불투명하게 글자를 덮는다.** 채움 기본값이나 그리는 순서 문제로
  보인다. 아직 코드로 확인하지 않았다 — 추측이다.
- **차트가 통째로 비어 있다.** 차트는 슬라이드가 아니라 `charts/chartN.xml`
  에 따로 들어 있고, 그걸 그리려면 차트 렌더러가 필요하다. 작은 일이 아니다.

## 4. 한글 — 표를 아예 안 그린다

이게 제일 크다.

hwpers 의 렌더러가 내보내는 요소는 네 가지뿐이다:

```
Text / Line / Rectangle / Image     (render/renderer.rs)
```

레이아웃 엔진(`render/layout.rs`)에는 **표라는 개념이 없다.** 모델
(`model/control.rs`)에는 표가 있지만 렌더러가 집지 않는다.

한국 업무 문서는 표가 반이다. 그대로면 표가 통째로 빠지거나 글자만 흩어진다.

**선택지**

1. hwpers 에 표 레이아웃을 더한다 — 쪽 나누기와 셀 병합까지 가야 해서
   작은 일이 아니다. 다만 코드가 작고(렌더 5.5천 줄) MIT 다.
2. HWPX 만 우리가 직접 그린다 — ZIP + XML 이고, 우리는 이미 `pdf-writer` 와
   폰트 처리를 갖고 있다. hwp(바이너리)는 hwpers 에 맡긴다.
3. 사용자의 실제 파일을 보고 정한다. **지금은 이것이 맞다** — 표가 없는
   문서라면 지금 것으로 충분할 수도 있다.

## 다시 써야 할 것이 있는가

**없다.** MiniPdf 의 구조는 멀쩡하다 — 엑셀 서식도 수식도 한글도 정확히
읽는다는 것을 시험으로 봤다. 문제는 전부 **정책과 빠진 분기**이지 설계가
아니다.

hwpers 는 다르다. 렌더러가 얇다. 다만 '다시 쓴다' 가 아니라 '표를 더한다' 로
끝날 수 있고, 그 판단은 실제 파일을 본 뒤에 한다.

## 순서

1. **워드 표 테두리** — 작고 확실하다
2. **엑셀 한 쪽 폭** — 가장 큰 불만을 없앤다
3. **한글 표** — 사용자의 hwp 결과를 보고 정한다
4. PPT 도형·차트 — 마지막. 차트는 별도 과제다

# 고친 결과 (2026-10-24)

네 항목 모두 코드까지 끝냈다. 기기 확인은 아직이다.

## 1. 워드 표 테두리 — 고침

`af2` 비교를 지우고 `w:tblBorders` 를 제대로 읽는다(`insideH`/`insideV`
포함). 표 스타일은 `based_on` 을 따라 올라가며 찾고, 셀의 `tcBorders` 가
물려받은 값을 이긴다. 시험 문서 두 개 — 스타일로 준 표와 인라인으로 준
표 — 둘 다 이제 격자가 나온다.

## 2. 엑셀 한 쪽 폭 — 고침

`ConversionOptions.fit_sheet_width` 를 더하고 앱에서 켠다. 쪽 폭을 시트
폭에 맞춰 늘리므로 열이 한 번도 안 잘리고 행만 아래로 넘어간다. 글자를
줄이지 않는다 — 화면에서는 뷰어가 다시 맞춘다.

14열 45행 견적 시트: 3쪽 → 1쪽. 200행: 15쪽 → 5쪽.

## 3. 한글 표 — 고침, 그리고 그보다 큰 것이 나왔다

표가 안 보인 이유는 레이아웃 엔진이 아니라 **레코드 태그 표가 14만큼
밀려 있었기** 때문이다. HWP 5.0 의 BodyText 태그는 `HWPTAG_BEGIN(0x10) + N`
인데 hwpers 는 PARA_HEADER 를 0x50 으로 적어 두었다. 진짜는 0x42 다.

그래서:

- PAGE_DEF(0x49) 를 영원히 못 찾았다 → "Section must have page definition"
  패닉 → 앱이 죽었다. A4 로 때운 것은 증상만 가린 것이었다.
- TABLE(0x4D) 과 LIST_HEADER(0x48) 를 못 알아봤다 → 표가 통째로 안 보였다.
- 컨트롤 ID 도 두 글자로 적혀 있었다. 실제는 네 글자다 — `'tbl '`
  은 0x74626C20.

태그를 바로잡고 레코드의 level 로 중첩을 따라가게 고쳤다. `'tbl '` 컨트롤이
표를 열고, TABLE 레코드가 격자와 행별 셀 수를 주고, LIST_HEADER 마다 셀이
하나 열리며 그 뒤의 문단이 그 셀의 글이다. 레이아웃 엔진은 그 격자를
한글이 적어 둔 폭과 높이대로 놓고(본문보다 넓으면 비례해 줄인다),
렌더러가 칸과 글을 그린다.

덤으로 글을 조용히 먹던 것 둘:

- 줄 자르기가 **앞 줄 시작 ~ 이 줄 시작** 이었다. 한 줄짜리 문단은 늘
  0..0 이라 글이 한 자도 안 나왔다. 게다가 UTF-16 위치로 바이트를 잘랐다.
- 문단 모양이나 글자 모양 번호가 범위 밖이면 문단을 통째로 버렸다.

변환기가 "문단 N개, 표 N개, 칸 N개, 쪽 N장" 을 로그에 남긴다. 기기에서
표가 안 보이면 못 읽은 것인지 못 그린 것인지 이 한 줄로 갈린다.

## 4. PPT 도형·차트 — 고침

도형은 전부 네모로 그렸다. 둥근 네모, 네 방향 화살표, 갈매기, 마름모,
삼각형, 육각형, 사다리꼴, 십자, 흐름도 도형에 제 모양을 줬다. 모르는
도형은 여전히 네모다.

도형 위의 글은 파워포인트처럼 가운데에 놓고, 색은 `style/fontRef` 에서
가져온다 — 남색 도형 위의 검은 글씨가 흰 글씨가 된다. 글상자와
자리표시자는 원래 정렬을 지킨다.

차트는 `ppt/charts/chartN.xml` 을 읽어 직접 그린다. 세로·가로 막대, 선,
원·도넛. 눈금선, 반올림한 값 축, 범주 이름, 범례, 테마 강조색.

## 남은 것

- 한글 표의 셀 배경색과 테두리 종류(`borderFillId` 를 아직 안 쓴다).
- 차트: 누적 막대를 묶은 막대처럼 그린다. 분산형도 선으로 그린다.
- 엑셀: 셀 글이 옆 칸으로 넘칠 때 자르는 규칙이 엑셀과 다르다.
