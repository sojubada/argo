## 1. 통일할 것

### 툴바

형식마다 조금씩 다릅니다. 하나로 맞추십시오.

```
[◀] [▶]  [3 / 12 쪽]  [맞춤▾]  [야간]  [배경]  [× 닫기]        파일명…
```

- 왼쪽부터 **이동 → 위치 → 보기 → 모드 → 닫기**, 제목은 맨 뒤에서 가운데가 잘림
- **조작 버튼이 먼저입니다.** 제목을 앞에 두면 긴 파일명이 뒤를 화면 밖으로 밀어냅니다 (실제로 당했습니다)
- `배경` 은 pptx 에서만
- 글자 26pt 이상. 3미터에서 읽어야 합니다
- 8초 뒤 자동으로 숨고, 선택 버튼으로 다시 뜹니다

### 보기 배율 — `맞춤` 버튼

사용자 요청입니다. **모든 형식**에 넣으십시오.

| 모드 | 동작 |
|---|---|
| 가로 맞춤 | 쪽 너비를 화면 너비에 (기본) |
| 세로 맞춤 | 쪽 전체가 한 화면에 |
| 원본 | 100% |
| 두 쪽 | **PDF 전용** — 나란히 두 장 |

웹뷰 쪽은 CSS 변수 하나로 처리하면 깔끔합니다.

```js
nav.fit = function(mode){ /* 'width' | 'height' | 'actual' | 'spread' */ };
```

### 책장 넘기기 — PDF

두 쪽 보기에서 쪽을 넘길 때 CSS `transform: rotateY()` 로 넘기는 효과. 이전 PDF 뷰어에 있던 것이고 사용자가 좋아했습니다.

`rotation3DEffect` 로 하던 것을 CSS로 옮기면 됩니다. **0.25초를 넘기지 마십시오.** 느린 전환은 금방 거슬립니다.

### 야간 모드

지금은 컨테이너에 `filter: invert(1) hue-rotate(180deg)` 입니다.

> **주의.** 이 방식은 **흰 바탕 문서에만 맞습니다.** 색이 있는 슬라이드에 걸면 허옇게 날아갑니다. 이전 PDF 뷰어가 바로 그 문제였습니다.
>
> 쪽의 평균 밝기를 재서 **이미 어두운 쪽은 반전하지 마십시오.** 캔버스를 작게(예: 40×22) 뽑아 픽셀 평균을 구하면 됩니다. 밝기 0.5 이상만 반전.

| 버튼 | 동작 |

## 3. 형식별로 더 할 것

### 엑셀 — 셀 서식

SheetJS 무료판은 **값과 병합만** 줍니다. 색·테두리·글꼴은 안 옵니다.

직접 읽을 수 있습니다. `xl/styles.xml` 의 `cellXfs` → `fills`/`borders`/`fonts`, 셀의 `s=` 가 그 인덱스입니다. JSZip으로 풀어 파싱하면 됩니다. **분량이 있으니 다른 것이 끝난 뒤에 하십시오.**

열 너비(`<col width=>`)와 행 높이도 같은 곳에서 나옵니다. 이건 비교적 간단하니 먼저 해도 됩니다.

### PPT — 두 갈래

지금 `pptx-preview` 는 **소스가 비공개(유료)** 입니다. 마스터 배경을 안 그리는 문제를 고칠 방법이 없습니다.

[pptx-viewer.us](https://github.com/MichalAFerber/pptx-viewer.us) 가 **MIT 오픈소스**입니다. 자체 OOXML 파서, 단일 HTML 파일. 스스로 "마스터 배경은 생략"이라고 밝히지만 **우리가 고칠 수 있다는 점**이 다릅니다.

→ **먼저 두 개를 같은 덱으로 나란히 돌려 비교하십시오.** 어느 쪽이 더 나은지 보고 결정합니다. 바꾸는 것 자체가 목적이 아닙니다.

**WMF 그림은 어느 쪽이든 안 됩니다.** 윈도우 전용 벡터 형식이라 브라우저가 못 그립니다. 그 자리에 "그림(WMF) — 표시할 수 없음" 정도의 자리표시를 넣으면 빈칸보다 낫습니다.

### 한글 — hwpx 가 안 됩니다

지금 `hwp.js` 는 2020년에 멈췄고 `.hwp` 만 됩니다.

**`@rhwp/core`** (npm, MIT, Rust+WebAssembly)가 **hwp 와 hwpx 둘 다** 합니다. Hoply 앱이 쓰는 것입니다.

**단, 확인이 먼저입니다.** 12MB WASM이고 tvOS WebKit에서 WebAssembly가 도는지 아직 모릅니다.

```js
typeof WebAssembly + ' / ' + (WebAssembly && typeof WebAssembly.instantiate)
```

`object / function` 이 나오고 12MB 모듈이 2GB 기기에서 버티면 갈아탑니다. **안 되면 hwp.js를 유지하고 hwpx는 포기합니다.** 짐작으로 진행하지 마십시오.

## 4. 큰 파일

지금은 문서를 **base64로 페이지에 실어** 보냅니다. 20MB 한글 파일이 27MB 문자열이 됩니다.

`allowFileAccessFromFileURLs` 를 이미 켜 두었으니 **파일을 그대로 두고 웹뷰가 읽게** 할 수 있을지 모릅니다. 확인해 보고, 되면 base64를 버리십시오. 안 되면 지금 방식이 안전망입니다.


3-D 는 **먼저 확인하고 보고하십시오.** 결과를 보고 할지 말지 정합니다.
